# Engineering Principles Skill

Use this skill when designing, implementing, refactoring, or reviewing
software.

## Protocol

1. Identify the behavior and the boundary that owns it.
2. Choose the smallest design that satisfies the requirement.
3. Check cohesion, coupling, responsibility, dependency direction, and
   substitutability.
4. Apply SOLID, Clean Code, KISS, DRY, and YAGNI only where they improve
   clarity or changeability.
5. Make side effects, invalid states, and failure behavior explicit.
6. Verify the result with focused tests or other repository checks.

Use `.core/engineering-principles.md` as the detailed reference. Do not force
object-oriented patterns onto functional or data-oriented code.
